# 日々の記録・職員考察：ノウビーの書き方に合わせる修正（2026-10-10 Claude）

基準：Codex 公開コード c4acdd4（引継ぎ文書に全文があった `lib/groundedDailyAi.ts`・`lib/dailyGrounding.ts` を改訂）。
c4acdd4 は GitHub に無いため、このフォルダーに「置き換えるファイル」と「組み込み手順」をまとめています。アプリ本体（app/）はまだ変えていません。

集計対象：2026-07-01〜10-01（約2,000件、10/06集計）と 2026-09-09〜10-08（655件、26名）。どちらも件数・文字数・言い回しの頻度だけを使った。

| | 日々の記録（中央値・多い範囲） | 職員考察 | 書き方 |
|---|---|---|---|
| 在宅（72%） | 343字（300〜370） | 177字（155〜190） | 4段落。見出しは `09:38作業開始の連絡頂きました。（○○対応）` が84%。考察1行目 `チラシ折り5setされました。` |

- 記録の語尾：「〜とのことでした」「〜されていました」「〜と報告がありました」「〜と話されました」「〜をお伝えしました」。
- 考察：今日の様子（「開始時から〜」）→ 見立て（「〜ができています」「〜と考えられます」）→「今後も〜支援していきます。」（約9割）。

## 2. 現行の文章がノウビーと違っていた原因
1. **見出しの書式が逆**：`formatDailyRecord` が「09:38に作業開始のご連絡を頂きました」へ統一していた（ノウビーでは7%の書き方）。
2. **通所・施設外にも考察1行目の作業量を強制**していた（ノウビーでは0件）。
3. 末尾指示「今日のメモをです・ます調へ書き直し」が考察も「書き直し」扱いにし、見立てと方針が薄くなる。
4. 見本が送られず、Qwen3 が事業所の形を真似る手がかりが「最近の記録2件」だけだった。
5. 単語の完全一致チェック：「眠い→眠気」のような正しい言い換えを止める一方、「今後」を含む文は前半の根拠なしの評価ごと素通り。職員の声かけ・休憩・連絡などの作り話は検出できなかった。
6. 字数が足りない時の書き直しを固定の下限で頼むため、事実の少ない日に水増しを促していた。

## 4. 正本への組み込み手順（Codex）
1. `lib/dailyGrounding.ts`・`lib/groundedDailyAi.ts` をこのフォルダーの版に置き換え、`lib/dailyStyle.ts` を追加。
2. `lib/dailyAssistant.ts` の `buildPrompt`：
   - `const mode=resolveMode(入力の利用の形, memo)`。
   - system を `systemPrompt(mode)` に置き換える（現行の system 全文は不要）。
   - user の `【利用の形】` 行は `mode==='未指定'?'未指定（推測しない）':mode`。
   - user 末尾の「上の今日のメモをです・ます調へ書き直し、…」を `userTail(mode,memo)` に置き換える。
   - `target` を固定表から `lengthPlan(mode,memo).target` に変更。戻り値に `distinct: exemplars[mode].distinct` を追加。
   - それ以外（資料6件・各5000字、最近の記録2件・各500字、伏せ字、未来日付の状態を使わない処理）は変えない。
3. `app/api/daily-assistant/generate/route.ts`：`groundedDailyAi(config,prompt,memo,{distinct:prompt.distinct})`。
4. `addResponder`：見出しの書式が変わるため、`insertResponder(record,name)` を使って `（○○対応）` を見出しの直後に付ける形に合わせる。**現行が「ご連絡を頂きました」に一致させて挿入している場合、そのままだと対応職員が表示されなくなる**ので必ず確認。
5. 画面の文字数の目安表示があれば `styleTargets` に置き換える。
6. テスト：`node handoff/20261010_daily_knowbe_style/tests/run-tests.mjs`（架空データ20件。Node 24 の型除去で実行、外部送信なし）。正本の scripts へ移す場合は import 先を調整。
7. 型チェック・ビルドのあと、実AI（Qwen3 30B）で架空4例を確認（下の基準）。

## 6. 実データでの確認（ローカルのみ・集計値）
655件のノウビー実記録を使い、本文は画面・ファイルに出さず件数だけ集計。
- 同じ人の**前回の記録の文**を今日の文章に混ぜたと仮定した時の検出率：記録 33.9% → **66.2%**、考察 18.8% → **31.5%**。
- 残りは「作業を開始されています」のような一般的な文で、実害の小さいものが中心。規則チェックは意味の正しさを保証しない。

## 7. 未対応・提案
- 実AI（Qwen3）での文章の確認は未実施（このPCに鍵が無い）。Codexまたは鍵の登録後に5の基準で確認する。
- ノウビーの記録が長い主な理由は「職員の声かけ・体調確認の内容」が毎回書かれていること。メモに無ければAIは書かないので、ノウビー並みの長さにするには、入力画面に「職員の対応」のかんたん入力（例：休憩を促した／作業量を一緒に確認した／手順を一緒に確認した）を足すのが最も効果的。画面の変更になるため、ユーザーの了承後に実装する。
